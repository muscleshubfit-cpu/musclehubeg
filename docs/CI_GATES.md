## 1. الفكرة (النص المنقول من README)

الريبو مش معتمد على النوايا الحسنة — معتمد على **بوابات**.
مع كل push وكل pull request، GitHub Actions بتعيد اشتقاق الحقيقة من الكود نفسه، وبتفشل بصوت عالي على أي كذبة: مرآة schema انزاحت، وثيقة عدت، معرّف متقاعد رجع يظهر، أو ميجريشن هتكسر الداتابيز. البوابة الواقفة بتمنع الدمج — على runners بتاعة جيت هاب نفسها، مستقلة تمامًا عن أي جهاز محلي أو جلسة AI.

**كل بوابة تحت اتولدت من حادثة إنتاج حقيقية، وبعدين اتحولت لكود دائم:**

| البوابة | بتشتق / بتلقط إيه | الحادثة اللي بنتها |
|---|---|---|
| **Schema-drift audit** — `scripts/migration_audit.py` | بيفكك كل ميجريشن، ويقارن الـschema الناتج بمرآة `types.ts` الميدانية + baseline مقبول موثق؛ أي جدول/عمود فانتوم أو ناقص **جديد** = فشل الدفع (وضع `--ci`) | أعمدة فانتوم في المرآة وقّفت خط ميجريشنز الإنتاج الحي (`42703`) وكسرت مسارات أعضاء بصمت |
| **Registry parity** — `scripts/docs_parity.py` | بيعيد عدّ الميجريشنز على القرص كل تشغيل — ترويسة سجل `INDEX.md` لازم تتساوى مع حقيقة الفايل سيستم | الوثائق اتجمدت على مرحلة قديمة والمنتج فضل يشتغل؛ الانجراف عدّ شهور من غير حد يشوفه |
| **Knowledge operating system** — `scripts/docs_audit.py` | سلامة `STATE.md` (≤100 سطر، أقسامها الإلزامية، والكوميت المسجل فيه لازم يكون سلفًا لـHEAD — الحالة عمرها ما بتشاور لقدام) · تساوي المرحلة عبر STATE/PROGRESS/QA · **صفر** عدادات متغيرة في README/DEVELOPER_GUIDE (قانون المصدر الواحد للأرقام — الأرقام بيتها الكود) · ممنوع تكرار أرقام الأقسام في `AGENTS.md` · وثائق حية نحيفة بمؤشرات أرشيف | حقائق مكتوبة في أماكن متعددة عدت بشكل مختلف — وملف القانون نفسه مرة شال §3.6 مكرر |
| **Anti-regression guard** — `scripts/check-stale-refs.sh` + `scripts/check-ui-wiring.sh` | فشل سريع على أي معرّف متقاعد رجع (روايتس متشالة، كومبوننتس ميتة، أسماء خطوط أنابيب قديمة) وعلى توصيل UI مكسور: أهداف fetch ميتة، أنواع jobs من غير معالج، معالجات من غير jobs، إنهاءات runner غير صادقة | روايتس AI متقاعدة فضلت شغالة بالتوازي مع الطابور الجديد — صنف «edits vanish» اللي المالك شافه بعينه |
| **Supabase Preview** | كل دفعة بتتطبق على داتابيز preview حقيقية عبر أكمال Supabase GitHub — ميجريشن واحدة فاشلة بتوقف الخط قبل ما توصل للإنتاج | اتعملت إثبات لايف: عمود واحد وحش جمّد دفتر الميجريشنز وسدّد صمت كل الميجريشنز اللي وراه |

**فوق البوابات، كل دفعة بتشغّل البطارية القياسية:** TypeScript `strict` · ESLint · مجموعة Vitest كاملة — كل البوابات zero-dependency وبتشرح الفشل inline (`::error::`) وبتخلص في ثواني.

**ليه ده مهم:** الوثائق مش ممكن تكذب، والمرآة مش ممكن تنزاح، والكود المتقاعد مش ممكن يرجع من الموت، وحالة المشروع الحالية دايمًا موجودة في [`STATE.md`](../STATE.md) — مدخل مُدار بقراءة 30 ثانية. وعلشان البوابات ساكنة جوه الريبو نفسه (`.github/workflows/` + `scripts/`)، بتسافر تلقائيًا مع أي نسخة نظيفة أو rebrand في المستقبل. ده اللي يخلي الريبو آمن للتطوير بمساعدة الوكلاء: أي جلسة، بشرية أو AI، تقدر تثق في الباب الأمامي من غير حفريات أثرية.

## 2. سجل الأعمال (Workflows) — البوابات عايشة فين

البوابات كلها ملفات تعريف داخل `.github/workflows/` والمنطق داخل `scripts/`:

| Workflow | الملف | الدور |
|---|---|---|
| Docs & schema parity gate | `docs-parity-gate.yml` | يشغّل `docs_parity.py` ثم `docs_audit.py` مع كل push/PR |
| Anti-regression guard | `guard-stale-refs.yml` | يشغّل `check-stale-refs.sh` + `check-ui-wiring.sh` مع كل push/PR |
| Supabase Preview | (تكامل Supabase GitHub، مش ملفنا) | تطبيق الميجريشنز على preview مع كل push — الفشل يوقف الخط |
| Process AI jobs | `process-ai-jobs.yml` | عامل طابور `ai_jobs` (جدولة + dispatch) — بيفشل بصدق لو أي job فشل نهائيًا |
| Auto-publish AR / EN article | `blog-post-ar.yml` / `blog-post-en.yml` | خط أنابيب المدونة v3 منفصل اللغات (3 فتحات يومية لكل لغة) |
| Remediate blog images | `remediate-blog-images.yml` | إعادة توليد صور المقالات القديمة عبر خط السلامة (workflow_dispatch) |

> قواعد ملزمة للمهام الجديدة على البوابات: أي سكربت ي referenced بـworkflow لازم يتدفع **في نفس الكوميت** (مناعة الجدولة/الحارس — «حارس مش متكمّم مش حارس»)، وأي تعديل يلمس التشغيل يُختبر بـdispatch يدوي قبل الاعتماد عليه.

## 3. أوامر التحقق القانونية (من AGENTS.md §3.5 — المرجع الحاكم)

```bash
npx tsc --noEmit          # 1. TypeScript — 0 أخطاء
npx eslint .              # 2. ESLint — 0 أخطاء
npx next build            # 3. بناء Next.js — exit 0 (لو الشغل لمس rendering/routes)
git push origin main      # 4. دفع للأمام فقط (ممنوع --force بدون توجيه صريح من المالك)
git fetch origin --quiet && git rev-parse HEAD && git rev-parse origin/main
                          # 5. تحقق المزامنة — الاثنين لازم يتطابقوا
git status --short        # 6. شجرة العمل نظيفة
```

«يتجمّع» مش نفسها «يشتغل» — التحقق الوظيفي > smoke test > فحص الأنواع. أي route اتلمس بيتسموكي محليًا بـcurl قبل أي ادعاء نجاح.

## 4. قوانين مكملة من AGENTS.md تخص صحة البوابات

- **قانون مكافحة الانحدار (§8):** إيقاف أي شيء (route/component/script/step) = `git rm` + كنس المستدعين + تصحيح التعليقات في **نفس الكوميت**، صفر ملفات شواهد قبور، ثم `check-stale-refs.sh` يطلع 0 قبل الدفع؛ والحارس يعيد الفحص على كل دفعة. عند «سلوك رجع للوراء» افتح `/api/build-info` وقارن `commitShort` بأحدث SHA على main — عدم تطابق = تأخر/فشل deploy، ممنوع تصحيح كود ضد deploy قديم.
- **لون التشغيل الصادق (§8):** أي runner داخل `scripts/*-runner/*` لازم يحمل مسار exit غير صفرى صريح (مفروض بـCI) — تشغيل أخضر معنى الحقيقي الوحيد: `done=N failedPermanent=0`.
- **مناعة الجدولة (SCHEDULE HEALTH LAW):** جدول جيت هاب ممكن يسجّل خروج صامت لكل workflows المجدولة — أي بلاغ «المدونة واقفة» بيبدأ بجنائيات الجدولة (`GET /actions/runs?event=schedule`) مش بإعادة قراءة كود الأنابيب؛ والعلاج: تمكين كل workflow + كوميت يلمس ملفاتها لإعادة التسجيل؛ والظهر المستقل: `/api/cron/dispatch-pipelines` (فشل مغلق، CRON_SECRET) بيكمّل حصة اليوم الناقصة يوميًا 21:00 UTC.
- **حادثة Phase 110 الموثقة (2026-09-03):** worker الـAI قعد أحمر على «Install dependencies» بانهيار npm 10 arborist (`Cannot read properties of null (reading 'edgesOut')`) ضد metadata الريجستري بتاريخ اليوم — الريبو بلا lockfile فالتثبيت بيحل فريش كل مرة، وnpm 11.17 حل نفس الشجرة سليمة محليًا → خطوة «Bump npm (npm install -g npm@11)» اتضافت قبل التثبيت في كل الـworkflows المكشوفة الأربعة. الدرس: فشل «Install dependencies» في CI يُشخّص كطبقة بنية تحتية أولًا قبل الشك في كوميت الكود.
